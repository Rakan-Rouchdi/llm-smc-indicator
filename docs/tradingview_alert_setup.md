# TradingView Alert Setup

Phase: 4A

Status: prepared only. Do not create the TradingView alert until the exact configuration below is approved.

This setup connects the existing `SMC LLM Candidate Detector` Pine indicator to the local FastAPI backend while keeping the mock LLM, mock news, and mock Telegram context active.

## Backend Prerequisites

Run the backend locally:

```bash
cd backend
source .venv/bin/activate
uvicorn app.main:app --reload
```

Confirm it is healthy:

```bash
curl http://localhost:8000/health
```

The backend accepts both webhook paths:

```text
POST /webhook/tradingview
POST /webhooks/tradingview
```

The backend supports either:

- `X-Webhook-Secret: <WEBHOOK_SECRET>` header
- `?secret=<WEBHOOK_SECRET>` query parameter

TradingView's native alert UI should use the query parameter unless the request is routed through an intermediate service that can inject headers.

## Pine Payload Contract

The indicator emits dynamic JSON through:

```pine
alert(payload, alert.freq_once_per_bar_close)
```

The payload is built inside `pine/smc_llm_candidate_detector.pine` and includes all required fields from `schemas/setup_alert.schema.json`:

- `schema_version`
- `setup_id`
- `source`
- `symbol`
- `root_symbol`
- `companion_symbol`
- `timeframe`
- `bar_time`
- `bar_index`
- `direction`
- `rule_score`
- `price`
- `entry`
- `risk`
- `features`
- `session`
- `diagnostics`

The Pine-style example payload is stored at:

```text
examples/pine_alert_payload_example.json
```

## Exact TradingView Alert Configuration

Do not create this alert until approved.

Use this configuration in TradingView's Create Alert dialog:

```text
Condition:
SMC LLM Candidate Detector -> Any alert() function call

Indicator input:
Enable alert() JSON payloads = true

Webhook:
Enabled

Webhook URL:
https://<public-backend-host>/webhooks/tradingview?secret=<WEBHOOK_SECRET>

Message:
Use the script-generated alert() message. Do not paste static JSON into the message box.

Alert name:
SMC LLM Candidate Detector webhook
```

The webhook request body will be the dynamic JSON string generated by Pine's `alert(payload, ...)` call.

## Localhost And Tunnel Requirement

TradingView sends webhooks from TradingView's servers, so it cannot reach `localhost` on your Mac directly.

If the backend only runs locally, a public HTTPS tunnel or deployed HTTPS endpoint is needed. TradingView accepts webhook URLs on ports 80 and 443 only, so do not put `:8000`, `:8001`, `:8002`, or `:8003` in the TradingView webhook URL.

Supported URL shape:

```text
https://<public-host>/webhooks/tradingview?secret=<WEBHOOK_SECRET>
```

Local tunnel options to consider, without installing anything yet:

- ngrok: exposes a local server through a public HTTPS forwarding URL.
- Cloudflare Tunnel: can publish a local service through Cloudflare; quick tunnels can expose localhost for development.

Do not install or start a tunnel until approved.

## Current Security Notes

- Keep `WEBHOOK_SECRET` out of the Pine payload body.
- Use the `secret` query parameter only over HTTPS.
- Rotate the secret after public testing.
- Do not expose the local dashboard publicly unless protected by an auth layer.
- Do not create TradingView alerts until the configuration above is explicitly approved.
